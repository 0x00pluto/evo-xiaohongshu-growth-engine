# 收纳插件（intake-plugin）

把来源项目收成当前工作区里的 `plugins/<id>/`，并在 `AGENTS.md`「插件」表与 `docs/doc_index.md` 登记。

**仅**在用户明确要求「收纳插件 / 把这个项目收成插件 / intake-plugin」时触发。任务结束**不**自动跑。当前任务已经是收纳时，禁止套娃。

已装插件的日常使用（人对口令）走 `AGENTS.md`「插件」节，**不**走本篇。卸插件不在本篇。

## 入口

```text
1. 打开当前工作区（一次只雇本仓）
2. 确认 AGENTS.md 的 scaffold_version 已含插件约定（≥ 本内置流所在母版号）；否则先按 CHANGELOG 跟升宿主，再回来
3. 阅读本篇全文
4. 按「日常步骤」执行；缺来源路径或 id → 停，按失败排查问询
5. 验收：存在 plugins/<id>/；插件表有一行；doc_index 有对应流程行；宿主 owns/not、内置流、既有业务流未被改写
```

本工作流由 Agent 对话驱动。不提供 Python CLI。

## 参数

| 输入 | 说明 |
|---|---|
| 当前仓路径 | 默认即打开的工作区根目录 |
| 来源路径 | 要收纳的项目根目录（脚手架、已跑项目、或任意同类目录）；**问用户**，禁止猜 |
| `id` | 插件目录名，小写英文 + 短横线；**问用户**；须唯一 |
| 版本 | 来源项目自己的版本（如其 `wiki_scaffold_version` / 包 version / CHANGELOG 当前号）；无则问用户；**不**与宿主 `scaffold_version` 混用 |
| 口令表 | 来源里「人说什么就读哪篇」；收纳后改写为指向 `plugins/<id>/docs/` 内路径 |

## 收纳对照

收进去的是可复用的那一块，按行放入 `plugins/<id>/`：

| 来源里有什么 | 放进 |
|---|---|
| 资料树、原文、知识页、模板、日志 | `plugins/<id>/assets/` |
| 口令可复跑的流程、命名约定、页面骨架说明 | `plugins/<id>/docs/` |
| 可复跑命令 | `plugins/<id>/scripts/` |
| 行为开关、超时、默认参数 | `plugins/<id>/configs/` |

缺哪类就省略哪类，**不**预建空夹。

**不收进插件、留在宿主上的：**

- 整份 `AGENTS.md`、`scaffold_version`、内置流（含本篇）
- 工牌、发版说明、这个仓才有的 `owns` / `not`
- 只服务这一个仓、换宿主就没有意义的业务流（留在宿主 `docs/workflows/`，需要时再调用插件）

## 清单

每个被收进去的插件在 `plugins/<id>/` 内自带一份清单（建议 `plugins/<id>/PLUGIN.md` 或同级约定文件名，跟插件包走）：

| 字段 | 说明 |
|---|---|
| `id` | 与目录名一致 |
| `version` | 插件自身版本 |
| `requires_scaffold` | 宿主脚手架下限（本母版起为 `2.7.0`） |
| `commands` | 口令 → `docs/` 内相对路径 |
| `do_not_overwrite` | 升级时禁止覆盖的路径（通常含已有资料页、原文、日志旧条目） |

## 日常步骤

```text
确认宿主已认插件
→ 问清来源路径与 id（及版本）
→ 若 plugins/<id>/ 已存在 → 走「升级」分支；否则走「新建收纳」
→ 按对照拷入可复用块；写/更新清单
→ 手术补丁 AGENTS「插件」表（追加或改版本/口令）
→ 追加 docs/doc_index.md 插件流程行
→ 自检：前缀隔离、宿主业务未动、资料旧条目未覆盖
```

### 新建收纳

1. **问清**：来源路径、`id`、版本；缺一不可。
2. **建目录**：只建本轮需要的 `plugins/<id>/assets|docs|scripts|configs/`。
3. **拷入**：按「收纳对照」复制可复用文件；路径与双链改写为带 `plugins/<id>/` 前缀。
4. **写清单**：落盘 id / version / requires_scaffold / commands / do_not_overwrite。
5. **补 AGENTS**：在「插件」表追加一行（id、版本、目录、口令 → 读）；空表占位行删掉或改成真实行。
6. **补 doc_index**：为该插件主要流程各追加一行摘要（路径指向 `plugins/<id>/docs/...`）。
7. **停**：不要改宿主 `owns` / `not`，不要改内置流正文，不要改宿主既有 `docs/workflows/`。

### 升级（同 id 已存在）

1. 读已装清单与来源变更记录；按该插件自己的 hop **逐跳**升级。
2. **只追加 / 覆盖**插件声明允许覆盖的文件；`do_not_overwrite` 与已有资料页、原文、日志旧条目**保持不动**。
3. 更新清单 `version`；更新 AGENTS 插件表该行版本与口令（若有变）。
4. `doc_index` 只补新流程行，不删业务条目。

## 产物

- `plugins/<id>/`（含对照后的子树与清单）
- 更新后的 `AGENTS.md`「插件」表一行
- 更新后的 `docs/doc_index.md` 相关行

## 失败排查

| 现象 | 处理 |
|------|------|
| 缺来源路径或 `id` | **停**；问用户，禁止编造 |
| 宿主尚无「插件」节 / 目录表无 `plugins/` | 先按脚手架 CHANGELOG 跟升到含插件的版本，再跑本篇 |
| `id` 与已有插件冲突且用户要新建 | 换 `id`，或确认走升级分支 |
| 误把宿主整份 AGENTS / 内置流拷进插件 | 删掉误拷；宿主文件保持原样 |
| 升级覆盖了已有 wiki / 原文 / 日志旧条 | 从备份或 git 恢复；将该路径写入 `do_not_overwrite` |
| 用户未明确要求却想收纳 | **停** |

## 测试

- 仅凭「日常步骤」能完成一次新建收纳。
- 收纳后：`plugins/<id>/` 存在；AGENTS 插件表有该行；`doc_index` 有指向插件 docs 的行；宿主能力声明与既有业务 workflows 未改。
- 同 id 再跑一次：走升级分支，资料旧条目仍在。
