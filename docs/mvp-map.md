# 增长引擎竖切地图

飞书《小红书获客产品设计文档》是引擎全貌。小红书是第一块平台。TO C 课、TO B 培训、武汉本地小课是选题的输入，不是三套软件。

发布按用户故事地图竖切：骨干从左到右是人要走完的事，每一刀从中间穿过去，出口是人手能复制去发、或能接着用的一篇稿。洞察、矩阵、词库、钩子、合规、回流是把某一列加厚，不能单独成为一刀的终点。

本文件只定顺序和边界。页面和生成器按第一刀另开实现，不在本文件里写。

## 骨干

```text
定题 → 写成一篇图文 → 人手复制去发 → 记下这篇结果 → 下一篇更准
```

飞书第十四章的七步（业务盘点、人群洞察、账号矩阵、内容规划、词库 / GEO、承接 SOP、数据回流）是骨干上的加厚项，不是发布顺序。先有一篇能发的稿，再把某一列做厚。

放大器（事件营销、达人、投流）排在后面。每一刀仍要落回一篇稿，或一个能执行的决定。

## 竖切

每一刀写清：人从哪进、中间故意做薄的一段、出口、这一刀不做。

### MVP-1 一天能发一篇

边界以 `specs/prds/prd-00001-one-post-from-article.md` 为准。封面那句话和封面类型以 `specs/prds/prd-00002-cover-feed-hook.md` 为准。

- **进**：一句业务（品牌、卖什么、对谁说）必填；一篇文章可选。有文章时只作素材。
- **中间**：不单独出选题列表。口吻锁一种素人号图文，骨架锁成「开头钩子 → 三点干货 → 结尾一句」。成稿只出标题、正文和话题。封面那句话由句子模块写出，并写进封面生图提示词。模型再在故事句和对比里选一种，套用该类型的画面结构。大字规则和语气一样只装填进选中的类型，不单独请求模型。文字是主角：主标题约占画面宽度的九成，文字区约占四成五，信息流大字，不走影视写实。对比的两个状态只用短标签，不在中间再塞一整句总题。配图仍是一次调用，0–9 条（默认 1 条）。人在配图页看见每条提示词，一次只生一张，同一张可以再抽。文案用 DeepSeek，生图用 Replicate 上的 GPT Image 2，比例 3:4。
- **出**：人可以复制去发的一整篇：标题、正文、3 到 5 个话题、封面那句话、1 张封面，以及 0–9 张配图。封面那句话由封面流程产出，不随成稿一起返回。
- **不做**：八类动机引擎、四类账号矩阵、词库爬取、视频、口播分镜、自动发布、数据回流、运行时连接飞书表。

### MVP-2 选题有得选

- **进**：同一句业务。
- **中间**：出 3 个选题，人选 1 个，再生成那一篇。
- **出**：仍是一篇可复制的图文稿。
- **不做**：在三个选题之外加账号矩阵或词库。

### MVP-3 这篇稿知道自己的角色

- **进**：生成前把这篇标成流量、信任、转化之一。
- **中间**：口吻仍先锁一个号。骨架沿用上一刀。
- **出**：仍是这一篇，角色写在稿上。
- **不做**：四类账号一起排期。

### MVP-4 发之前改危险词

- **进**：同一篇稿。
- **中间**：过广告法极限词、站外引流词、违禁词，给出替换建议，人改完再定稿。
- **出**：改过的这一篇。
- **不做**：谐音、拆字、表情规避。

### MVP-5 发出去记一笔

- **进**：已经发出的这一篇。
- **中间**：手填播放、赞藏评、私信。下一篇定题时能看见上一篇的数字。
- **出**：一篇稿加上它的结果。
- **不做**：截图识别、自动拉数。

### MVP-6 词进标题

- **进**：人手维护的少量词，加上一句业务。
- **中间**：选题和标题前部用上一个核心词。
- **出**：标题里带核心词的这一篇。
- **不做**：爬搜索下拉、相关搜索、第三方数据工具。

### MVP-7 稿子自带承接

- **进**：同一篇稿。
- **中间**：结尾钩子和评论区第一条引导写进这篇。
- **出**：带承接句的这一篇。
- **不做**：独立话术库、活码系统。

### 再往后

- **事件**：一篇承接稿，加上一张发布节奏。
- **达人**：一份 brief。
- **投流**：对这一篇给出投或不投。

这三刀不做一键爆款、一键投流。

## 红线

- 不自动批量发布、评论、私信、回评。
- 不模拟登录爬取数据。
- 不批量去他人评论区截流。
- 不照搬对标原文和图片。
- 不使用未授权客户证言，不造假案例。
- 不用敏感词变体对抗平台。
- 不教批量养号。
- 不与捞客仓对接。

「可以发」指稿子能复制到小红书，由人点发布。

## 页侧

操作台用 HTML First：一份 HTML，Alpine 写状态，需要控件时用 daisyUI 5 浅色。页面底保持白，强调色只出现在按钮和标记上。不上构建链，不上 Next.js，不上 htmx（读写走 JSON）。

Dex Buddy 把插件页面开在隔离窗口里，按钮走 `window.dex.call`。宿主运行说明要求不要把 Next.js 页面嵌进工作台。

离开 HTML First 要同时满足两件：操作台变成多路由产品，并且设计系统已经锁在 React。在那之前保持现在的页侧。

## 源码和页面分开

Studio 只放页面。选题、成稿和以后的加厚项放在 `src/` 的其他包。页面和仓库根的薄桥可以调用这些包；这些包不能引用 `src/studio`。

本文件不建目录。下一轮按第一刀实现时按这个形状长：

```text
plugin.manifest.json          # 仓库根，Dex Buddy 合同；uiEntry 指向页面；icon 指向 icon.png
index.js                      # 仓库根薄桥：dex.call 转到 src 里的包
src/studio/static/index.html  # 只有页面
src/topic/                    # 选题
src/draft/                    # 成稿
```

后面的竖切再加新包，例如 `src/compliance`、`src/review`，不把逻辑堆进 studio。

仓库约定不在根目录散文件。Dex Buddy 的插件根就是本仓，清单和 `index.js` 必须在根上，只此两份合同文件，业务源码不放根。
