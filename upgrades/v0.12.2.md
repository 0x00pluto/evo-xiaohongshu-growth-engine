# v0.12.2

相对 `v0.12.1`：修复 Windows 中文用户名下 Native Host 登记失败、资料库识别不到 Chrome 取料插件的问题；Host 脚本改放入会进插件包的 `src/`。

## 变更

- **Windows Host 安装目录**：用户目录含中文等非 ASCII 时，Host 与清单改写到 `C:\ProgramData\DexBuddy\native-host`（创建失败再落到 `C:\Users\Public\DexBuddy\native-host`）；英文用户名仍用 `%LOCALAPPDATA%\DexBuddy\native-host`。
- **解释器路径**：仅 Windows `.cmd`；`DexBuddy.exe` / Node 路径含中文时在安装目录建 `runtime-bin` 联接，只把 ASCII 路径写入包装器。
- **插件包**：Host 可执行脚本迁到 `src/xhs-note/dexbuddy-native-host.js`（会进 `dex-buddy-plugin.pack` 的 `src/`）；`scripts/dexbuddy-native-host.js` 仅作旧入口转发。`index.js` / 操作台 / 安装 CLI 改指新路径。
- **macOS**：仍用 `~/Library/Application Support/DexBuddy/native-host`，不写 `C:\` / ProgramData。
- **文档 / 测试**：FAQ 与工作流排障补充 Windows 中文用户名说明；补安装目录选择与中文扩展路径 origin 用例。

## 升级注意

- clone / 切换到本 tag：`git clone --branch v0.12.2 <origin>`
- 核对根目录 `evo_agent_pack.json` 的 `version` 为 `0.12.2`（不含 v）
- `plugin.manifest.json` 的 `version` 须同为 `0.12.2`
- Windows 中文用户名机器：打开一次增长引擎（触发静默登记）后，在 `chrome://extensions` 重载内部特供版，并打开「允许 Dex Buddy 连接」
- 不要搬智赢扩展安装目录；扩展路径可含中文，ID 仍按真实路径计算
